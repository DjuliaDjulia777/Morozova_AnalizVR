# Отчёт об анализе временного ряда дорожного трафика (Junction 1)

## 1. Описание временного ряда
- **Источник:** [Kaggle Traffic Prediction Dataset](https://www.kaggle.com/datasets/fedesoriano/traffic-prediction-dataset)  
- **Объект:** перекрёсток №1 (Junction 1)  
- **Период:** 2015-11-01 – 2017-06-30  
- **Частота:** почасовая (14 592 наблюдения)  
- **Целевая переменная:** количество автомобилей (`Vehicles`)  
- **Пропуски:** отсутствуют  

## 2. Постановка задачи прогнозирования
- **Горизонт:** 168 часов (1 неделя)  
- **Метрики:** MAE (средняя абсолютная ошибка), RMSE  
- **Валидация:** hold-out (последняя неделя) + бектестинг на 3 исторических окнах  
- **Бейзлайн:** SeasonalNaive (MAE = 15.40, RMSE = 18.78)  

## 3. Разведочный анализ (EDA)
- **Суточный профиль:** пики в утренние и вечерние часы (07:00–09:00 и 17:00–19:00), минимум ночью (03:00–05:00).  
- **Недельная сезонность:** будние дни значительно загруженнее выходных (среднее Пн–Пт ≈ 48–51, Сб–Вс ≈ 32–34).  
- **Стационарность:** тест Дики–Фуллера отвергает наличие единичного корня (p‑value = 0.0000). Ряд стационарен, но содержит выраженную сезонную структуру.  

## 4. Анализ аномалий
Для выявления аномалий использованы три метода:

| Метод            | Количество аномалий | Параметры                          |
|------------------|---------------------|------------------------------------|
| IQR              | 177                 | Коэффициент 1.5                    |
| Isolation Forest | 273                 | contamination = 0.02               |
| STL-остатки      | 195                 | period = 24, порог 3σ              |

**Выбран метод STL-остатков**, так как он учитывает тренд и суточную сезонность, а порог 3σ даёт интерпретируемые границы, устойчивые к колебаниям трафика.

## 6. Обоснование параметров моделей
- **AutoETS** – автоматический выбор компонент (ошибка, тренд, сезонность) с суточным периодом 24.  
- **Theta** – модель декомпозиции с фиксированным сезонным периодом 24.  
- **AutoARIMA** – автоматический подбор порядков (p,d,q)(P,D,Q,s) с сезонностью 24.  
- **ARIMA(2,0,1)(1,0,1,24)** – несезонные лаги выбраны по ACF/PACF (резкий спад после 2–3 лагов), сезонная часть отражает суточный цикл.  
- **ML-модели (LinearRegression, LightGBM, XGBoost):** использованы признаки – лаги (1,2,3,6,12,24,48,168), скользящие среднее и стандартное отклонение за 6 и 24 часа, час, день недели, месяц. LightGBM и XGBoost обучены на 100 деревьях с параметрами по умолчанию.  
- **DL-модели (LSTM, NBEATS, MLP):** input_size = 24 (LSTM) и 168 (NBEATS, MLP), max_steps = 50, стандартный скейлер, обучение без дополнительных ковариат.  
- **Pipeline (LightGBM)** – рекурсивный прогноз на шаг вперёд с теми же признаками, обучен на всей истории, не подглядывает будущие лаги.  

## 7. Итоговый пайплайн
Пайплайн реализован в виде функции `forecast_pipeline(train_series, horizon)` в файле `pipeline.py`:
- Генерация признаков: лаги, скользящие статистики, временные метки.
- Модель: LightGBM (100 деревьев).
- Прогноз: рекурсивный (пошаговый) с добавлением каждого предсказания обратно в историю для вычисления лагов.

**Результаты статистического тестирования на 3 исторических окнах:**
- Окно 1: MAE = 4.34, RMSE = 5.39
- Окно 2: MAE = 4.64, RMSE = 6.29
- Окно 3: MAE = 6.53, RMSE = 8.94
- **Среднее:** MAE = 5.17 ± 0.97, RMSE = 6.88 ± 1.51

Пайплайн стабилен, разброс метрик приемлем для практического использования.
